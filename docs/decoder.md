## 用語

| 用語 | 意味 |
|---|---|
| Goertzel (ゲルツェル) | 1 つの周波数の成分の強さだけを求める計算法です。FFT ですべての周波数を求めるより計算が軽いのが特徴です |
| FFT | Fast Fourier Transform (高速フーリエ変換)。入力に含まれる各周波数の成分の強さを、まとめて求める計算法です |
| ビン | Goertzel や FFT で強さを求める周波数の点です。中心ビン = 受信周波数、サイドビン = その両脇の周波数 |
| 受信周波数 | 受信しているトーンの周波数です (TONE で選んだ周波数、または TONE AUTO で合わせた周波数) |
| 窓 | 1 回の計算に使う入力の範囲です (直近の何サンプル分を使うか) |
| 平均 (EMA) | EMA は Exponential Moving Average (指数移動平均)。新しい値が来るたびに「平均 = 平均 + (新しい値 − 平均) × 係数」で更新する平均です。係数が小さいほどゆっくり動きます |
| 単位長 | 短点 1 個の長さです。長点は 3 単位、符号内のスペースは 1 単位、文字間は 3 単位、語間は 7 単位が標準です |
| マーク / スペース | トーンが出ている区間 / 出ていない区間です |
| WPM | Words Per Minute。1 分間に送る語数で、CW の速さを表します |
| ALE | Adaptive Line Enhancer (適応型ラインエンハンサ)。入力から周期的な成分 (トーン) だけを強めるフィルタです |
| NLMS | Normalized Least Mean Squares (正規化最小二乗平均) 法。ALE のフィルタの係数を自動で調整する計算法です |
| NR | Noise Reduction (ノイズ低減)。SETUP の `NR(ALE)` のことです |

ソースは `src/dsp.cpp` (トーン検出・ALE・自動同調)、`src/decoder.cpp` (判定・速度推定・符号の組み立て)、
`src/decode.cpp` (符号から文字への変換、欧文 / 和文) です。

## 全体の流れ

```mermaid
flowchart TD
    A["ADC 32kHz<br>4 点平均で 8kHz"] --> B["直流分を除く"]
    B --> C["Goertzel で強さを求める (生入力)<br>中心 / 近サイド / 遠サイド"]
    B --> D["ALE<br>(NR ON のとき)"]
    D --> E["Goertzel で強さを求める (ALE の出力)<br>中心"]
    C -- "純音かどうかの判定 (サイドとの比)" --> F
    C -- "振幅 (NR OFF のとき)" --> F
    E -- "振幅 (NR ON のとき)" --> F
    F["ON / OFF 判定<br>3.75ms ごと"] --> G["ノイズブランカ"]
    G --> H["マーク長・スペース長の測定"]
    H --> I["速度推定"]
    H --> J["短点 / 長点 / 区切りの判定"]
    I --> J
    J --> K["符号 → 文字<br>(欧文 / 和文)"]
    S["FFT 256 点"] --> T["TONE AUTO<br>(受信周波数を合わせる)"]
    B --> S
    T -- "受信周波数" --> C
```

矢印はデータの流れです。ON / OFF 判定には、純音かどうかの判定 (サイドとの比) と振幅の 2 つを渡します。
純音の判定にはいつも生入力の値を使い、振幅には NR が OFF なら生入力の値、ON なら ALE を通した値を使います。
TONE AUTO は、FFT で見つけた信号の周波数を受信周波数として設定します。

DSP (信号処理) とデコーダは ESP32 の Core 0、画面の描画とタッチは Core 1 で動きます。

## 入力

- ADC (Analog-to-Digital Converter: アナログ / デジタル変換器) で、GPIO35 (ADC1_CH7) の音声を 32kHz で取り込みます。
  取り込みには DMA (Direct Memory Access: CPU を通さずにメモリへ転送する仕組み) を使い、4 点ずつ平均して 8kHz にします。
- 入力には約 1.65V のバイアス (直流分) が乗っているので、ゆっくり動く平均で求めて差し引きます。
- ADC の手前のアナログボードに、BPF (Band-Pass Filter: 帯域通過フィルタ) があります
  (中心 700Hz、Q=5。通す帯域の幅は約 140Hz です。[回路図](schematic.pdf) を参照してください)。

## トーン検出

Goertzel で、受信周波数とその両脇 4 か所の周波数の強さを求めます。

| ビン | 位置 | 役割 |
|---|---|---|
| 中心 | 受信周波数 | トーンの振幅 |
| 近サイド | 中心 ±133Hz | トーンより幅の広いノイズを見つける |
| 遠サイド | 中心 ±267Hz | 全体に広がるノイズや、パルス状の雑音を見つける |

**窓とブロック**

- 1 回の計算には、直近 120 サンプル (15ms) の入力を使います (窓)。窓が長いほど帯域が狭くなり (66.7Hz)、ノイズが入りにくくなります。
- 計算は新しいサンプルが 30 個 (3.75ms) 入るたびに行います (ブロック)。窓を 30 サンプルずつずらすので、帯域を狭く保ったまま 3.75ms 刻みで判定できます。

  ```
  time -------------------------------->
  #1  [================]                  120 サンプル (15ms)
  #2      [================]              30 サンプル (3.75ms) ずらす
  #3          [================]
  #4              [================]
  ```

- 45WPM 以上では窓を 60 サンプル (7.5ms) に縮めます。窓が長いと、速い CW では符号の間の短い無音が埋もれてしまうためです。

**サイドビンでトーンとノイズを見分ける**

- Goertzel は 15ms の入力だけで計算するので、近い周波数どうしは完全には区別できません。
  たとえば 700Hz のトーンを 750Hz で測っても、ある程度の値が出ます。
- ただし周波数の差が 66.7Hz (= 1 ÷ 15ms) の整数倍のときは、15ms の間に差の分がちょうど 1 周 (2 周…) して打ち消し合い、0 になります。
- サイドビンはこの位置 (66.7Hz の 2 倍と 4 倍) に置いてあるので、トーンだけならサイドビンはほぼ 0 です。
  ノイズはいろいろな周波数を含むので、サイドビンにも値が出ます。
- つまり、中心だけが大きければトーン、サイドも大きければノイズです。
- 遠サイドの低い側と高い側は、掛け合わせて平方根をとった値 (**相乗平均**) で 1 つにまとめます。
  低い周波数ほど強いノイズのように、片側だけが大きいときもノイズを少なく見積もらないためです。

FFT は画面のスペクトラム表示と TONE AUTO にだけ使い、トーンの判定には使いません。

## ノイズ低減 NR (ALE)

SETUP の `NR(ALE)` が ON (既定) のときは、ALE (Adaptive Line Enhancer: 適応型ラインエンハンサ) を使います。

- ALE は、少し前 (2ms 前から 8ms 分) の入力から、いまの入力を予測するフィルタです。
- トーンは同じ波形を繰り返すので予測できますが、ノイズは予測できません。
  そのため予測した値 (ALE の出力) は、トーンが強く、ノイズが弱くなります。
- 予測に使う係数は、NLMS (Normalized Least Mean Squares: 正規化最小二乗平均) 法で、予測の誤差が小さくなるように自動で調整します。
- ALE の出力は**振幅**にだけ使い、**純音かどうかの判定** (サイドとの比) は生の入力で行います。
  ALE の出力でサイドと比べると、ノイズまでトーンに見えてしまうためです。

ON にすると弱い信号を拾いやすくなり、ノイズから偽の文字が出にくくなります。

## トーンの ON / OFF 判定

ブロックごとに、次の条件でトーンの ON / OFF を決めます。
ON と OFF の条件を別々にしてあり、どちらも満たさないときは直前の状態を保ちます (境目で ON と OFF が細かく入れ替わらないように)。

| | 条件 |
|---|---|
| ON (すべて満たしたとき) | 振幅 > しきい値 × 0.6<br>中心 > 遠サイド × 3<br>中心 > 遠サイドの大きいほう<br>中心 > 近サイド × 2.0 |
| OFF (どれか 1 つを満たしたとき) | 振幅 < しきい値 × 0.4<br>中心 < 遠サイド × 2.5<br>中心 < 近サイド × 3.2 |

- **しきい値**は、直前のマークの振幅に合わせて自動で動きます。上がるときはすぐ追いつき、下がるときはゆっくり下がります。
- しきい値は、**ノイズ床** (ノイズの平均的な大きさ) の 8 倍より下げません。ノイズ床はトーンが無いと思われるブロックだけで平均します。
  しきい値がノイズに合わせて動くので、入力の音量によらず同じように受信できます。

## ノイズブランカ

ON / OFF の判定結果から、短いばたつきを取り除きます。

- カウンタを用意し、ON のブロックで 1 増やし、OFF のブロックで 1 減らします。上限に達したら ON、0 になったら OFF にします。
- 上限は単位長の約 0.35 倍 (2〜5 ブロック) です。ON になるときも OFF になるときも同じだけ遅れるので、マークの長さは変わりません。

## 速度推定

単位長 (短点 1 個の長さ) を推定します。範囲は 24〜300ms (50〜4WPM) で、WPM = 1200 ÷ 単位長 (ms) です。

- 主にマークの長さを使います。0.6〜2 単位のマークは短点、2〜6 単位は長点とみなします。
- 直前のマーク (またはスペース) との長さの比がおよそ 3 倍なら、短点と長点の組とみなして単位長を直接求めます。
  それ以外は、マークの長さに向けて推定を少しずつ近づけます。
- 直近 8 個のマークに短点と長点 (1:3) の組があれば、そこから単位長を求め直します。推定が大きくずれても、ここで立て直せます。
- ノイズらしいマーク (短すぎるもの、長い無音のあとに単独で出たもの) は推定に使いません。

## 符号内・文字間・語間の判定

スペースの長さで、符号内 (短点・長点の間)・文字間・語間を見分けます。

- **符号内と文字間の境界**は、測った符号内スペースの長さと、標準の文字間 (3 単位) の中間に置きます。
  符号内スペースが短点より長い送り手 (キーイングの重みが重い送信) でも、1 文字がばらばらになりません。
- **文字間と語間**は、4.5 単位未満を文字間、6 単位以上を語間とします。

## 文字の確定とノイズ文字の抑止

- 文字間・語間を見つけたとき、または無音が 6 単位を超えたときに、それまでの短点・長点の並びを文字にします。
- 欧文 / 和文の符号表は `src/decode.cpp` にあります。和文モードでは「ホレ」で和文、「ラタ」で欧文に自動で切り替わります。
  略符号 (プロサイン) の AR / KN / BT / VA / HH / BK と、U と R を続けて送る `UR` は 2 文字で表示します。
- ノイズだけのときは E / T が続けて出やすいので、直近 12 文字のうち E / T が 9 個以上ある間は、E / T を表示しません。

## TONE AUTO (自動同調)

TONE が AUTO (既定) のときは、500〜1000Hz で最も強い信号に受信周波数を自動で合わせます。信号を見つける前は 600Hz で待ちます。

- 45ms ごとの FFT で、ほかより十分強い周波数が 3 回続けて同じ位置に見つかったら、受信周波数をそこへ動かします。
- 受信中 (トーン ON) は小さな修正だけを行い、別の局へは移りません。
- 符号の隙間 (トーン OFF) に出たノイズに引っぱられないよう、遠くへ移るのは今の信号より十分強い候補があるときだけです。

## 実装上の注意点

- **変数どうしの掛け算・割り算を使わない** (判定・速度推定):
  このデコーダには、小さなマイコン CH32V003 / CH32V006 で動く版 ([UIAP_CWDecoder2](https://github.com/pokibon3/UIAP_CWDecoder2)) があり、
  デコードの処理を共通にしています。CH32V003 には掛け算と割り算の命令が無いので、
  決まった数を掛ける計算と、2・4・8… で割る計算だけで書いています。
- **大きなメモリは後から確保する**: スコープ表示用と ALE 用のメモリは、起動時の更新チェックが終わってから確保します。
  更新チェックの暗号化通信が、空きメモリをぎりぎりまで使うためです。
