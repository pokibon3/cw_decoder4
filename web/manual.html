CW Decoder 4 — 使い方 ブラウザで動くモールス信号デコーダ。ESP32 版のファームウェアと同じ信号処理を そのまま WebAssembly で動かしています。インストールは不要です。

1. まずは動かしてみる

無線機もマイクも無しで試せます。テスト信号タブを開いて 送信を押してください。内蔵の CW 発生器が符号を送り、 デコードされた文字が画面に出ます。

S/N のスライダーを下げていくと、ノイズの中でどこまで読めるかが その場で分かります。WPM とトーン周波数も変えられます。

2. 音声の入れ方

画面上部のタブで 4 通りから選びます。

マイク / ライン入力

実際に無線機の音をデコードするときはこれです。 無線機の AF 出力 → USB オーディオ I/F → PC が最も確実で、 FT8 (WSJT-X など) を運用されているならまったく同じ配線がそのまま使えます。 新しい機材は要りません。

PC 内部で鳴っている音 (SDR ソフトなど) は、仮想オーディオループバックを経由すると拾えます。 macOS なら BlackHole、Windows なら VB-CABLE やステレオミキサーです。

開始を押すとブラウザがマイクの使用許可を尋ねます。許可すると デバイス一覧に実際の名前が出るので、再検索を押して使う入力を選び直してください。 取り込みを止めるときは隣の終了を押します (どの入力元でも止まります)。

エコーキャンセル・ノイズ抑制・AGC は自動で無効化しています。 これらが効いているとブラウザが CW を「ノイズ」とみなして消してしまい、 まったくデコードできません。実際に無効化できたかは、開始後に画面一番下の状態行へ表示されます。

マイク/ライン: (デバイス名) — 48000Hz / 2ch → L / 前処理なし

タブ音声

WebSDR や動画など、ブラウザの別タブで鳴っている音をそのままデコードします。 仮想ループバックを入れなくても使えるのが利点です。

共有ダイアログではタブを選び、タブの音声も共有するに 必ずチェックを入れてください。Chrome 系のブラウザのみ対応しています (Safari / Firefox は非対応)。

音声ファイル

WAV / MP3 などを読み込んでデコードします。同じ音源で何度でも再現できるので、 設定を変えたときの効き具合を比べるのに向いています。

ファイルを選ぶと、音量を自動で適正レベル (-12 dBFS) に合わせてすぐに先頭から 再生を始めます。先頭 / 5 秒戻し / 再生・一時停止 / 5 秒送り / 末尾 のボタンと シークバーで位置を操作できます。

再生位置を動かすとデコーダの状態はリセットされます。符号の途中から始まるためで、 飛んだ直後の 1〜2 文字は化けることがあります。

テスト信号

ハード無しで動作確認するための内蔵 CW 発生器です。WPM (8〜45)、トーン (450〜1050Hz)、 S/N (-6〜40dB)、送信する文字列を指定できます。

3. 画面の見方

場所内容
大きな文字エリア デコードされた文字。最新の 1 文字は緑で表示されます。 選択してコピーできるほか、コピーボタンで全文をクリップボードへ送れます。 和文モードではカタカナで表示し、濁点・半濁点は前の文字と合成します

LVL入力レベル (dBFS)。緑が適正、黄〜赤は過大。CLIP は振り切れ

FFT スペクトラム 約 300〜1200Hz。青い帯が TONE の選択レンジ (600〜1000Hz)、 黄色い帯がいま検出に使っている帯域、下の三角が中心です
オシロスコープ 生波形 (青)、トーンの強さ (アンバー)、キー判定 (緑のバー) を同じ時間軸で重ねています。 キーのバーの上に、その符号の位置でデコード文字が流れます
一番下の状態行 停止中 や、開いている入力デバイス・読み込んだファイルの情報。 エラーや警告も赤字でここに出ます

4. 操作

FFT / オシロをダブルクリック そのパネルを横幅いっぱいに広げる。もう一度で戻ります。 見出しのクリックでも切り替わります

5. うまく読めないとき

上から順に確認してください。

入力BPF が ON か

これが一番効きます。実機は ADC の手前にアナログのバンドパスフィルタが 入っており、デコーダのしきい値はその帯域制限された入力を前提に調整されています。 ブラウザには素の全帯域音声が入るので、BPF が無いと帯域外のノイズが 内部のノイズ床推定を押し上げ、しきい値が信号に迫ってしまいます。

ノイズ混じりの録音での実測では、BPF なし 44% → あり 93% (正解文との文字一致率) でした。

Q は上げすぎないでください。帯域を狭くしすぎると、 フィルタ自身がノイズを「純音らしく」整形してしまい、信号が無いのに文字が出ます。 純ノイズ 60 秒での偽文字は Q=3 で 0 個、Q=5 で 8 個、Q=8 で 144 個でした。 既定の 3.0 は、偽符号が出ない範囲で最大限ノイズを削れる値です。

ch の選択 (ステレオ入力のとき)

ステレオ I/F の片チャンネルだけに無線機を繋いでいる場合、L+R にすると 空いている側のノイズを足し込むことになります。合成信号での実測では、 条件によっては読めていたものが完全に読めなくなるほどの差が出ました。 信号の載っている側を選んでください。

入力レベル

レベルメーターが黄〜赤なら入力ゲインを下げます。目安は -24〜-12 dBFS です。 CLIP が点いていなくても、黄より右は過大です。

ブラウザの前処理

マイク入力の開始後、画面一番下の状態行に ⚠ noiseSuppression が無効化できていません のような警告が出たら、そのブラウザが無効化の要求を受け入れていません。 CW が消されてしまうので、別のブラウザ (Chrome 系) をお試しください。

sps 表示

LVL メーター右の実効入力レートが 8000 を割って赤くなっている場合、 音が取りこぼされています。符号の長さが狂うので速度推定ごと崩れます。 他の重いタブを閉じる、モニター音を切る、などをお試しください。

受信開始直後の 1 文字目

振幅しきい値と速度推定が収束する前に当たるため、化けることがあります。 これは実機と同じ挙動で、異常ではありません。

6. 仕様と制限

  • タブを裏に回すと画面の更新は止まりますが、デコードは動き続けます。 戻れば溜まった文字がそのまま出ます
  • マイクを使うには初回に許可が必要です。許可の記憶はブラウザごと・サイトごとです
  • タブ音声の取り込みは Chrome 系のみです
  • スマートフォンでも動きますが、iPhone / iPad はライン入力が無いため 音響結合 (スピーカーの音をマイクで拾う) になります
  • デコードの中核は ESP32 版ファームウェアと同一のソースを WebAssembly にしたものです。時計・WiFi・OTA など実機固有の機能はありません

モールスデコーダ部分は Hjalmar Skovholm Hansen OZ1JHM 氏の Arduino 用 CW Decoder を一部流用しており、オリジナルの GPL ライセンス条件が適用されます。
